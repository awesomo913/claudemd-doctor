# Code Style

- Format every file with the project formatter before committing; don't hand-format.
- Prefer small, single-purpose functions over long ones with multiple responsibilities.
- Name booleans as questions (`isReady`, `hasError`) so call sites read naturally.
- Avoid abbreviations in public function and variable names; spell words out.
- Keep a function's parameters under five; group related ones into an object.
- Comments explain why, not what — the code already says what it does.
