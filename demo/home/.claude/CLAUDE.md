# Demo Workspace Rules

This is a synthetic fixture for claudemd-doctor's own demo. Nothing here
describes a real project, and none of the paths or names below exist.

## Core workflow (HOT)
- Always run `npm test` before opening a pull request.
- Always use `npm` to install dependencies in this repo — the committed lockfile is npm's.
- Write commit messages in the imperative mood, e.g. `fix: handle empty input`.
- Keep pull requests under 400 lines when it's reasonable to split them.

## Code review
- Every pull request needs at least one approval before merging.
- Leave review comments as questions when you're not sure, not as commands.
- Prefer small, focused review rounds over one giant pass at the end.

## Communication
- Summarize what changed and why in the pull request description, not just what.
- Link the tracking ticket in every pull request description.
- Flag breaking changes in the first line of the description, in bold.

## Shared conventions
- See @shared.md for team-wide conventions shared across every project.
